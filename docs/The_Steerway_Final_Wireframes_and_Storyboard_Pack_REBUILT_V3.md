# 0. Critical correction in this V3 rebuild

The previous rebuild assumed too much about the hero section. That was incorrect.

The hero section is **not fully designed yet**. It must not be treated as a finalized visual composition, and the AI coding platform must not invent a complex hero structure, copy hierarchy, proof blocks, cards, dashboards, ecosystem visuals, or service grids.

The hero section is now defined only at the level needed for implementation safety:

```text
Hero = powerful typographic field + subtle CTA/scroll instruction + uploaded HTML vector-field background.
```

The uploaded HTML file is used for **one thing only**: the hero background field. Do not copy its hero copy, header, footer, HUD labels, cursor, layout, pricing, group references, Steer Intelligence wording, or any other section.

The corrected locked homepage order is:

```text
Needle calibration loader
-> Hero typographic field using uploaded HTML field background only
-> Service ticker bridge with centered primary seal
-> Primary-seal cinema
-> S-path square journey
-> Conversion bridge
-> STEERWAY footer payoff
-> Internal pages using needle mapping
```

# 1. Why this correction matters

The purpose of keeping the hero simple is to preserve clarity without letting the hero compete with the cinematic seal sequence.

The homepage has two different jobs:

1. **Hero section:** create immediate clarity and mood.
2. **Cinema sequence:** create the unforgettable brand experience.

The hero should not become the cinema. The hero should not attempt to show every service. The hero is a calm, powerful typographic field that prepares the user for the deeper journey.

# 2. Absolute hero rules

## 2.1 What the hero must contain

- A full-viewport or near-full-viewport hero field.
- The vector-field canvas background inspired only by the uploaded HTML hero background.
- One large powerful typographic statement.
- Optional short subcopy, if needed later.
- One subtle CTA or two very restrained CTAs.
- A scroll instruction, such as `Scroll to steer the way` or similar.

## 2.2 What the hero must not contain

- No cards.
- No service grid.
- No pricing.
- No dashboard mockups.
- No group ecosystem.
- No Blank Group references.
- No Steer Intelligence wording.
- No copied copy from the uploaded HTML file.
- No copied header, footer, cursor, HUD, or other sections from the uploaded HTML file.
- No invented final hero copy unless explicitly approved.

## 2.3 Hero copy status

The final hero copy is **TBD**. The AI platform may use placeholder tokens during build, but must not treat them as final copy.

Preferred placeholder format:

```text
[HERO_HEADLINE_TBD]
[HERO_SUBCOPY_TBD]
[PRIMARY_CTA_TBD]
[SCROLL_INSTRUCTION_TBD]
```

If temporary copy is needed for layout testing, use short neutral placeholders only and mark them as temporary.

# 3. Hero background field from uploaded HTML

![Corrected hero field wireframe](steerway_v3_final_assets/02_corrected_hero_field_wireframe.png){width=100%}

The uploaded HTML hero background contains a canvas-based field of small line segments. The lines respond to an attractor point, creating a directional field. Near the attractor, some strokes shift toward champagne. When idle, the attractor drifts in a smooth ambient orbit.

This is the only visual behaviour from the uploaded HTML that should be carried forward.

## 3.1 Background behaviour to implement

- Full-viewport canvas behind hero text.
- Dense grid of short line segments.
- Each segment rotates toward an attractor.
- Attractor follows cursor on desktop.
- Attractor moves gently by itself when idle.
- Nearby strokes become brighter and warmer/champagne.
- Distant strokes remain ivory/graphite, low opacity.
- Small champagne node dots may appear near high-attraction zones.
- Background must remain subtle enough for large typography to stay readable.

## 3.2 Background behaviour to avoid

- Do not use it as a loud particle system.
- Do not make it neon.
- Do not let it distract from hero typography.
- Do not import the uploaded site's HUD/cursor/header/contact/pricing sections.
- Do not include any `The Blank Group` or `Steer Intelligence` text.

# 4. Homepage architecture diagram

![Architecture V3](steerway_v3_final_assets/01_homepage_architecture_v3.png){width=100%}

The architecture must now be understood as three major acts:

1. **Opening clarity:** needle loader and hero field.
2. **Transition into world:** service ticker bridge and primary seal entry.
3. **Cinematic payoff:** seal-world journey, text reveals, conversion bridge, footer period.

# 5. Needle loader storyboard

![Needle loader](steerway_v3_final_assets/03_needle_loader_storyboard.png){width=100%}

The loader uses the secondary needle. It should be short, quiet, and directional.

Storyboard:

1. Dark field appears.
2. Needle appears and calibrates.
3. Needle rotates to 0 degrees toward the right.
4. Needle exits or traces toward the hero field.

The needle must not become the cinema. It is the opening instrument.

# 6. Hero and service ticker bridge

![Service bar bridge](steerway_v3_final_assets/04_service_bar_bridge.png){width=100%}

Below the hero, a premium service ticker bridge introduces the primary seal.

The ticker should feel like a slow, typographic system belt, not a cheap marquee.

Allowed terms:

```text
WEBSITES · AI AUTOMATION · SAAS PRODUCTS · CRM SYSTEMS · DASHBOARDS · ANALYTICS · GROWTH INFRASTRUCTURE
```

The primary seal only, not full wordmark, sits in the center or acts as the entry object.

A small instruction can appear:

```text
SCROLL TO STEER THE WAY
```

# 7. Cinema storyboard below service bar

![Cinema storyboard](steerway_v3_final_assets/05_cinema_storyboard.png){width=100%}

Everything below the service bar until the footer is the main cinematic canvas. This is where all the best reference-inspired behaviours belong.

Rules:

- Primary seal becomes the spatial world.
- S-route is derived from the seal geometry.
- Champagne square travels the route.
- Camera tracks the square.
- Text reveals in negative space.
- No cards, no boxes, no icons.
- Footer period is the same square.

# 8. Scroll zone ownership

![Scroll zone map](steerway_v3_final_assets/06_scroll_zone_map_v3.png){width=100%}

The hero owns mood and clarity. The cinema owns spectacle. Do not blur these jobs.

# 9. Reference-inspired micro-interactions

![Micro interaction matrix](steerway_v3_final_assets/07_micro_interaction_matrix.png){width=100%}

The reference learnings are not written as vague copy-this-site instructions. They are translated into build behaviours:

- Text reveal: large masked Fraunces reveal, mono label first.
- Hover text: champagne path underline, coordinate label, restrained magnetic shift.
- Cinema square: glow, trail, pulse, acceleration/deceleration.
- CTA: border trace, champagne signal, subtle pressure response.
- Footer word: period glow and micro S-route replay.
- Hero background: vector-field canvas from uploaded HTML only.

# 10. Internal-page wireframe system

![Internal pages](steerway_v3_final_assets/08_internal_pages_needle_mapping.png){width=100%}

Internal pages must not repeat the homepage cinema. They should use the secondary needle as a mapping device.

Examples:

- AI Automation: input -> decision -> output.
- Websites: visitor -> CTA -> lead routing.
- SaaS: idea -> architecture -> product.
- CRM/Dashboards: data -> pipeline -> reporting.
- Process: diagnose -> build -> measure.

# 11. AI-platform anti-deviation board

## 11.1 Hero-specific anti-deviation

Reject the implementation if:

- The hero uses copy from the uploaded HTML.
- The hero says Steer Intelligence.
- The hero references The Blank Group.
- The hero contains detailed service cards.
- The hero becomes a product/SaaS layout.
- The hero background is replaced with random particles instead of the vector-field canvas.
- The hero headline is treated as final without approval.

## 11.2 Cinema-specific anti-deviation

Reject if:

- Cinema starts before hero.
- Cinema uses cards or boxes.
- The square does not drive reveals.
- The path is not based on primary seal geometry.
- Footer period appears abruptly.

The hero section is intentionally not final-designed. Build a hero shell with powerful typography placeholders, subtle CTA/scroll instruction, and the uploaded HTML's canvas vector-field background only. Do not copy any other part of the uploaded HTML.
After the hero, build the service ticker bridge, then the primary-seal cinema with S-route square journey and typography-only reveals.
